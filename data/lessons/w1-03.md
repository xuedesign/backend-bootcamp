瀏覽器裡的 JavaScript 活在網頁裡。Node.js 讓同一種語言在你的終端機裡跑，用來啟動工具、安裝套件、開發 Worker。今天的目標不是變成終端機高手，是敢在黑底白字裡走路。

## 用生活例子理解

- **終端機**是一扇用文字開門的櫃台。你打一行指令，系統做一件事。
- **Node.js**是另一間可以跑 JavaScript 的房間。瀏覽器是客廳，Node 是工作室。
- **npm**是工作室的工具店。`package.json` 是購物清單。別人拿到清單，就能買到同一組工具。
- **套件**是別人寫好的工具。Workers 的開發工具 Wrangler 就是一個套件。

> 生活比喻：你不會把整間五金行搬去工地。你帶一張清單（`package.json` 與鎖定版本的 lock 檔）。同事照清單買，工具就對得起來。

路徑先記三個動作：

| 指令 | 做什麼 |
| --- | --- |
| `pwd` | 我現在在哪個資料夾 |
| `ls` | 這裡有哪些檔案 |
| `cd 資料夾` | 走進去。`cd ..` 是回上一層 |

## 動手做

大約 25 分鐘。請先安裝 Node.js 22（與這門課的網站相同）。裝好後，終端機輸入 `node -v`，應看到 `v22` 開頭。

1. 建一個練習資料夾並走進去：

```bash
mkdir node-hello
cd node-hello
```

2. 產生清單。一路按 Enter 用預設值即可：

```bash
npm init -y
```

3. 打開剛出現的 `package.json`。你會看到 `name` 與 `"type"` 可能還沒有。先不用改。
4. 新增 `hello.js`，內容用下面案例。
5. 執行 `node hello.js`。終端機應印出一句中文。
6. 再執行 `npm install cowsay`，看清單裡多了 `dependencies`，資料夾多了 `node_modules`。
7. 這個套件只是好玩。看完就知道：安裝會改 `package.json`，真正的檔案在 `node_modules`，不要手改那一層。

Windows 的 PowerShell 同樣可以用 `cd` 與 `mkdir`。列出檔案是 `dir` 或 `ls`。

## 案例

```js title=hello.js
const tool = "Node.js";

// 這支檔案由 node hello.js 執行，不是由瀏覽器打開。
console.log(`哈囉，我在 ${tool} 裡跑`);

const note = { course: "後端闖關", day: 3 };
console.log(JSON.stringify(note));
```

```json title=package.json
{
  "name": "node-hello",
  "private": true,
  "type": "module",
  "scripts": {
    "start": "node hello.js"
  }
}
```

`"type": "module"` 表示這個資料夾裡的 JavaScript 用 `import` / `export`，跟你在前端寫的 ES Module 同一套。今天的 `hello.js` 還沒有匯出東西，所以兩種都能跑。從明天的 Worker 開始，我們固定用模組寫法。

裝好之後可以用清單上的腳本：

```bash
npm start
```

`npm start` 會去跑 `scripts.start`。你不需要記住 node 的完整路徑。

## 常見錯誤

- 在錯誤的資料夾執行指令。先 `pwd`，確認自己在專案裡。
- 把 `node_modules` 上傳到 Git。那一層又大又能用清單重裝。這門課的 `.gitignore` 已排除它。
- 以為裝了 Node 就等於有伺服器。Node 能跑 JavaScript，但對外的網站還要你寫「收到請求時要回什麼」。那是明天的 Worker。
- 把終端機的錯誤當成失敗的人格。第一行通常寫著找不到檔案或指令。讀那一行就好。
