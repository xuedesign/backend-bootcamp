這一週的零件今天拼起來：REST 路徑、輸入驗證、CORS、環境變數。資料仍放在程式裡的陣列。它是原型，用來確認 API 的形狀，不是客人的留言會在的地方。

## 用生活例子理解

陣列像櫃檯上的白板。

- 這台 Worker 重啟，白板就擦掉。
- 平台可能同時跑很多份你的程式。客人 A 寫在某一塊白板，客人 B 連到另一塊，看不到 A 的字。
- 白板也沒有權限。任何人知道網址就能刪。

> 生活比喻：白板適合彩排走位。正式演出要換成會留檔的帳本。那是下一週的資料庫。

所以今天的完成標準是：本機能新增、列表、刪除，而且你能說出「為什麼這還不能佈署給真的使用者」。

## 動手做

大約 30 分鐘。完整專案在 `examples/02-guestbook-memory/`。

1. 複製該資料夾，或把案例的三個檔案放進新專案。
2. `npm install` 後 `npm run dev`。
3. 用瀏覽器打開 Worker 網址的 `/`。同一來源之下，這頁呼叫 `/api/messages` 不必靠 CORS。
4. 新增兩則留言，刪掉一則，重新整理。白板還在，是因為開發伺服器還沒關。
5. 停掉 Wrangler 再啟動，留言應消失。把這個現象寫進筆記。
6. 用 `curl` 送一筆超過 500 字的內容，確認是 `400`。
7. 做第 2 週測驗。通過後才打得開資料庫那一週。

## 案例

```js title=src/index.js
const messages = [];
let nextId = 1;

function readMessage(data) {
  if (!data || typeof data !== "object") return { error: "請傳送 JSON 物件" };
  const author = typeof data.author === "string" ? data.author.trim() : "";
  const body = typeof data.body === "string" ? data.body.trim() : "";
  if (author.length < 1 || author.length > 20) return { error: "作者請介於 1 到 20 個字" };
  if (body.length < 1 || body.length > 500) return { error: "留言請介於 1 到 500 個字" };
  return { author, body };
}

async function handleApi(request) {
  const url = new URL(request.url);
  const one = url.pathname.match(/^\/api\/messages\/(\d+)$/);

  if (url.pathname === "/api/messages" && request.method === "GET") {
    return Response.json(messages);
  }

  if (url.pathname === "/api/messages" && request.method === "POST") {
    let data;
    try {
      data = await request.json();
    } catch {
      return Response.json({ error: "請傳送 JSON" }, { status: 400 });
    }
    const parsed = readMessage(data);
    if (parsed.error) return Response.json({ error: parsed.error }, { status: 400 });

    const message = {
      id: nextId,
      author: parsed.author,
      body: parsed.body,
      createdAt: new Date().toISOString(),
    };
    nextId += 1;
    messages.push(message);
    return Response.json(message, { status: 201 });
  }

  if (one && request.method === "DELETE") {
    const id = Number(one[1]);
    const index = messages.findIndex((item) => item.id === id);
    if (index === -1) return Response.json({ error: "找不到留言" }, { status: 404 });
    messages.splice(index, 1);
    return Response.json({ deleted: id });
  }

  return Response.json({ error: "找不到這個路徑" }, { status: 404 });
}

export default {
  async fetch(request, env) {
    const url = new URL(request.url);
    if (url.pathname.startsWith("/api/")) return handleApi(request);
    return env.ASSETS.fetch(request);
  },
};
```

靜態頁面由 Workers 的靜態資源綁定來送。設定：

```jsonc title=wrangler.jsonc
{
  "$schema": "./node_modules/wrangler/config-schema.json",
  "name": "guestbook-memory",
  "main": "src/index.js",
  "compatibility_date": "2026-10-30",
  "assets": {
    "directory": "./public",
    "binding": "ASSETS",
    "run_worker_first": true
  }
}
```

`run_worker_first` 讓每個請求先進入你的程式。API 由你回答，其他路徑再交給 `env.ASSETS.fetch`，也就是 `public/` 裡的檔案。若沒有這行，平台會優先直接回檔案，`/api/...` 沒有對應檔案時才進 Worker，學習階段容易搞混誰先跑。我們明確寫成「程式先看」。

`public/index.html` 用 `fetch("/api/messages")`。因為頁面與 API 同一個來源，不必加 CORS。第 2 週仍要記得：來源不同時，標頭才要登場。

## 常見錯誤

- 把這個原型佈署給朋友使用，隔天留言不見，或有時看得到有時看不到。那是白板的特性，不是客人操作錯。
- `id` 用陣列長度，刪除中間一筆後又用長度當新編號，可能撞號。案例改用只增不減的 `nextId`。
- 刪除時沒找到仍回 `200`。呼叫的人會以為刪掉了。
- 在 `run_worker_first` 模式裡忘記把非 API 交給 `ASSETS`，首頁變成 404。
